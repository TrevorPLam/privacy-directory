# Privacy Compliance Rules

## Core Privacy Principles

### Neutrality Requirement
- **No Subjective Labels**: Never use "good", "bad", "ethical", or "unethical" when describing companies or practices
- **Factual Presentation**: Present only verifiable facts about data collection, sharing, and privacy practices
- **Source Requirements**: All data must cite verifiable sources (official documentation, privacy policies, regulatory filings)

### Data Minimization
- **Essential Data Only**: Collect only data necessary for the privacy directory's factual mission
- **No Personal Data**: Never collect personal user data in the directory itself
- **Analytics**: Use privacy-focused analytics (Plausible) with no tracking cookies

## Content Standards

### Company Information
- **Practice Descriptions**: Factual descriptions of data practices without judgment
- **Data Sensitivity Tiers**: HIGHEST | HIGH | MODERATE (purely informational)
- **Source Documentation**: Required URLs for all claims about company practices

### Privacy Incidents
- **Factual Reporting**: Report breaches, lawsuits, regulatory actions as documented facts
- **Source Verification**: All incidents must link to official sources or reputable news reports
- **No Speculation**: Avoid speculation about motives or unconfirmed impacts

### Data Broker Information
- **Opt-Out Processes**: Document factual opt-out mechanisms without evaluation
- **Compliance Status**: Report auditable compliance status objectively
- **Deletion Requests**: Track factual deletion request processes

## Technical Privacy Requirements

### Website Privacy Practices
- **No Tracking Cookies**: Use session storage only when necessary
- **Privacy Policy**: Transparent description of site's own data practices
- **Data Retention**: Minimal data retention, clear deletion policies
- **Third-Party Services**: Only privacy-focused services (Plausible analytics)

### User Data Handling
- **No Account System**: No user accounts or personal data collection
- **Contact Forms**: Client-side only, no server-side persistence in v1
- **Search Functionality**: Client-side search without user tracking
- **Interactive Tools**: Privacy-preserving design for opt-out tools

## Legal Compliance

### Jurisdiction Considerations
- **International Laws**: Consider GDPR, CCPA, and other relevant privacy laws
- **Data Localization**: Ensure compliance with data residency requirements
- **Cross-Border Data**: Minimize international data transfers

### Accessibility Standards
- **WCAG Compliance**: Ensure accessibility for all users
- **Plain Language**: Use clear, understandable language for privacy information
- **Multi-Language**: Consider translations for key privacy information

## Data Source Standards

### Verifiable Sources Required
- **Official Documentation**: Company privacy policies, terms of service
- **Regulatory Filings**: SEC filings, FTC complaints, GDPR breach notifications
- **Government Sources**: Regulatory agency websites, court documents
- **Reputable Journalism**: Established news organizations with editorial standards

### Source Citation Format
```markdown
**Source**: [URL](link) - Description of source type and date accessed
**Verification**: Method used to verify the information
**Last Updated**: Date of last verification
```

### Source Maintenance
- **Regular Verification**: Re-verify sources quarterly
- **Broken Links**: Monitor and update broken source links
- **Source Changes**: Track and document significant source updates

## Content Validation Rules

### Fact-Checking Process
1. **Source Verification**: Confirm source authenticity and reliability
2. **Cross-Reference**: Verify facts across multiple independent sources
3. **Date Relevance**: Ensure information is current and relevant
4. **Context Accuracy**: Present facts in proper context

### Prohibited Content
- **Unverified Claims**: Information without reliable sources
- **Personal Opinions**: Subjective judgments about companies or practices
- **Speculative Analysis**: Unsubstantiated predictions or interpretations
- **Defamatory Content**: Potentially libelous statements

## Error Correction Process

### Correction Policy
- **Prompt Corrections**: Correct errors within 24 hours of identification
- **Transparent Updates**: Clearly mark corrected information
- **Source Attribution**: Update sources when corrections are made
- **User Feedback**: Provide mechanism for reporting inaccuracies

### Quality Assurance
- **Regular Audits**: Quarterly content accuracy audits
- **Peer Review**: Internal review of significant content changes
- **External Validation**: Periodic external review of content standards

## Implementation Guidelines

### Development Standards
- **Privacy by Design**: Build privacy considerations into all features
- **Data Protection**: Implement technical measures to protect any collected data
- **User Control**: Provide users control over any data interactions
- **Transparency**: Clear communication about data practices

### Monitoring and Maintenance
- **Compliance Tracking**: Monitor changes in privacy regulations
- **Source Monitoring**: Track changes in company privacy practices
- **Technology Updates**: Stay current with privacy-enhancing technologies
- **Community Feedback**: Incorporate user feedback on privacy practices
